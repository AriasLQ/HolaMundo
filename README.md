## Principales Actividades Desarrolladas
Durante esta actividad realizamos los siguientes pasos:
1. Creación de repositorios personales y subida del programa base `HolaMundo.java` sin usar la rama master.
2. Selección de un repositorio central y creación de ramas individuales (ej. `HolaMundo_AriasL`, `HolaMundo_PatricioH`).
3. Modificación local del código por parte de cada integrante para agregar su nombre.
4. Subida (Push) de las nuevas versiones a las ramas correspondientes.
5. Integración de todas las ramas (Merge) a la rama principal, gestionando los conflictos generados al modificar el mismo archivo.
6. Creación de este archivo README y anexión de capturas de evidencia.

## Comentarios y Conclusiones
* Comentarios: -La dinámica demostró ser bastante eficiente. Tener un espacio separado para cada integrante funciona muy bien para evitar pérdida de tiempo. Es como tener un entorno de pruebas propio; te aseguras de que tu lógica funciona perfectamente antes de siquiera intentar juntarla con la de los demás.  
 -Lo mas importante para el desarrollo de este pequeño proyecto fue una buena coordinación y comunicación. Hubo un pequeño problema con respecto al entorno donde se desarrollaba el proyecto, ya que en nuestro caso trabajamos en dos versiones diferentes de pom.xml, a lo cual por decisión colectiva decidimos conservar una única versión (17) para finalizar con el proyecto

* Conclusiones: El uso de branches no es solo una buena práctica, es indispensable para optimizar el desarrollo. Aunque el momento de hacer merge puede generar conflictos si editamos las mismas líneas, la herramienta te da el control exacto para decidir qué versión conservar, asegurando que el resultado final sea siempre el correcto.
